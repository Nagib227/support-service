# Backlog

Оценки — плановые часы на реализацию истории вместе с проверкой. Приоритет P1 блокирует демонстрацию, P2 нужен для сдачи целиком, P3 усиливает эксплуатацию.

| ID | Задача | Приоритет | Часы | Результат |
| --- | --- | --- | --- | --- |
| US-1 | Регистрация заявки и валидация | P1 | 4 | `POST /api/tickets`, статус `NEW` |
| US-2 | Получение заявки и ответ 404 | P1 | 2 | `GET /api/tickets/{id}` |
| US-3 | Правка описания, приоритета и срока | P1 | 3 | `PATCH`, запрет для закрытых |
| US-4 | Правила переходов статуса | P1 | 5 | 400 / 404 / 409, время закрытия |
| US-5 | История статусов в одной транзакции | P1 | 3 | таблица `status_history` |
| US-6 | Фильтры, пагинация, просрочка | P1 | 4 | `GET /api/tickets` |
| US-7 | Справочник категорий | P2 | 2 | миграция и `GET /api/categories` |
| US-8 | Сводка на Kotlin | P1 | 6 | `GET /api/reports/summary` |
| US-9 | Единый формат ошибок | P1 | 3 | `ApiError` для 400, 404, 409, 500 |
| QA-1 | Модульные тесты правил и сводки | P1 | 4 | JUnit, Mockito |
| QA-2 | Интеграционные тесты с PostgreSQL | P1 | 5 | Testcontainers |
| QA-3 | Два сквозных сценария и регрессия D-1 | P1 | 3 | жизненный цикл и запрет 409 |
| OPS-1 | Docker Compose, health check, логи | P2 | 4 | `compose.yaml`, Dockerfile |
| OPS-2 | Резервная копия и восстановление | P2 | 2 | `scripts/backup.*`, `scripts/restore.*` |
| OPS-3 | Pipeline без деплоя на PR и с проверкой образа на main | P2 | 6 | GitHub Actions |
| DOC-1 | Спецификация, API, тест-план, отчёт | P2 | 4 | каталог `docs/` |

Сумма оценок backlog — 60 часов разработки и проверки. Оставшиеся часы учебного плана приходятся на анализ требований, проектирование и защиту; их результат — эта спецификация, диаграммы и README.
